1. A container is a lightweight, standalone, and executable software package that includes everything needed to run an application: code, runtime, system tools, libraries, and settings. Containers are isolated from each other and the host system, which allows for consistent environments across different stages of development and deployment. We need containers because they provide a way to package applications and their dependencies together, ensuring that they run reliably regardless of the environment.
2. containers and virtual machines (VMs) are both technologies that allow for the isolation of applications, but they differ in their architecture and resource usage. VMs run on a hypervisor and include a full operating system, which makes them heavier and slower to start. Containers, on the other hand, share the host operating system's kernel and are much lighter, allowing for faster startup times and more efficient resource usage. This makes containers more suitable for microservices and cloud-native applications.
3. docker architecture consists of several components:
   - **Docker Daemon**: The background service that manages Docker containers, images, networks, and storage volumes. It listens for Docker API requests and performs the requested actions.
   - **Docker Client**: The command-line interface (CLI) that allows users to interact with the Docker Daemon. Users can issue commands to build, run, and manage containers.
   - **Docker Images**: Read-only templates used to create containers. Images contain the application code, libraries, and dependencies needed to run an application.
   - **Docker Containers**: Running instances of Docker images. Containers are isolated from each other and the host system, providing a consistent runtime environment.
   - **Docker Registry**: A repository for storing and distributing Docker images. Docker Hub is a popular public registry, but private registries can also be set up.



list all running containers: ps
list all containers (including stopped ones): ps -a
stop and remove a container: docker stop <container_id> && docker rm <container_id>

running a containr in detached mode: docker run -d <image_name>, it helps to run containers in the background without blocking the terminal. You can check the status of detached containers using `docker ps`.
give a container a custom name: docker run --name <custom_name> <image_name>, this allows you to easily identify and manage containers by their names instead of their IDs.
map a port from the container to your host: docker run -p <host_port>:<container_port> <image_name>, this allows you to access services running inside the container from your host machine.
check logs of a running container: docker logs <container_id>, this command retrieves the logs generated by the container, which can be useful for debugging and monitoring.
run a command inside a running container: docker exec -it <container_id> <command>, this allows you to execute commands inside a running container, providing an interactive shell or running specific tasks without stopping the container.
